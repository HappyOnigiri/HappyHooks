# dangerous-rm-guard

[English](dangerous-rm-guard.md) | 日本語 · [hook 一覧](../../README.ja.md#hook-一覧)

**既定:** Claude Code のみ有効。

Claude Code の組み込み検査が確認プロンプトを出す `rm`・`rmdir` の形を先に拒否します。空になりうる変数で始まるパス、静的に解決できない対象、重要なディレクトリ、作業ディレクトリやその祖先などが対象です。

エージェントはユーザー待ちになる代わりに、対処できる理由文を受け取ります。
基本の判定は Claude Code v2.1.239 の規則に合わせ、`D=$S/$n; rm -rf $D` のような先行代入から派生した変数の削除は
v2.1.283 の規則に合わせています。

シェルに `-c` で渡すスクリプト（`bash -c '...'`）は v2.1.296 の規則に合わせています。
Claude Code が静的に検査できないスクリプト（sed の `\{0,1\}` のような括弧、`alias`、`IFS`、2000 文字超）で、
コマンドの位置にある語が実行時に `rm` になり得る（`$CMD x`、`direnv exec "$DIR"` など）ときに拒否します。
この判定はコマンドに `rm` が無くても働きます。検査できるスクリプトは、位置引数をリテラルの値に置き換えたうえで、中身を同じ規則で判定します。
`CLAUDE_CODE_DISABLE_INLINE_SHELL_RM_PROMPT` を設定すると、Claude Code とこの hook の両方でこの判定が止まります。
Claude Code はサーバー側の機能フラグでもこの判定を切れますが、hook からはフラグが見えないので、その場合は hook だけが拒否します。

その他の新しい判定とは異なる可能性があります。
