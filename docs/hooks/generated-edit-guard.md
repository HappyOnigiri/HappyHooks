# generated-edit-guard

English | [日本語](generated-edit-guard.ja.md) · [Hooks](../../README.md#hooks)

**Default:** On for Claude Code and Codex.

Stops agents from hand-editing generated files. A file counts as generated when its first 8 KiB contain the standard Go
marker (`// Code generated ... DO NOT EDIT.`) or a marker you configure. Paths that do not exist yet are not checked.

The hook checks the target of edit tools (`Edit`, `Write`, `MultiEdit`, `NotebookEdit`, `apply_patch`) and the files a
shell command writes: `sed -i`, `perl -i`, `tee`, `cp`, `mv`, `install`, `truncate`, `dd of=`, patches passed to `patch`
or `git apply`, code passed inline to `python`, `node`, `ruby`, or `perl` that calls a write API, and redirections from
commands that produce text by hand (`echo`, `printf`, `cat`, `sed`, `awk`, inline code). It follows `cd` in the command.

Reading a generated file and running a generator or script file are not blocked, even when the output is redirected
(`make l10n`, `go generate`, `python3 tools/gen.py`, `mockgen ... > x_mock.go`).

When it blocks an edit, it tells the agent to fix the generator's source and regenerate the file, naming the command
when the marker shows it (for example `'make l10n'` or mockgen's `Generated by this command:`). If the generator cannot
run, the agent is told to continue and list the needed change in its final report. It never asks for confirmation.

Add markers for files that do not use the Go convention in `~/.config/hhx/config.yaml`. Each entry is a Go regular
expression matched line by line against the start of the file:

```yaml
hooks:
  generated-edit-guard:
    markers:
      - "^// auto generate by 'make l10n'"
```

When the user explicitly tells the agent to edit a generated file, the agent runs this once:

```sh
hhx allow-generated-edit --reason "<the user's instruction>" path/to/file.go
```

The hook records the declaration for the agent session and allows edits of those paths for the rest of the session.
Each time, it reminds the agent to report the edited files, the reason, and the need to regenerate them.

The check is static. Paths built from variables, writes from script files, and commands such as `xargs` or file
deletion are not detected.
