# generated-edit-guard

[English](generated-edit-guard.md) | 日本語 · [hook 一覧](../../README.ja.md#hook-一覧)

**既定:** Claude Code と Codex で有効。

エージェントによる自動生成ファイルの手編集を止めます。ファイルの先頭 8 KiB に Go の標準のマーカー（`// Code generated ... DO NOT EDIT.`）か、設定したマーカーがあれば生成ファイルとみなします。まだ存在しないパスは調べません。

編集ツール（`Edit`・`Write`・`MultiEdit`・`NotebookEdit`・`apply_patch`）の対象と、シェルのコマンドが書き込むファイルを調べます。

シェルで調べるのは、`sed -i`、`perl -i`、`tee`、`cp`、`mv`、`install`、`truncate`、`dd of=`、`patch` や `git apply` に渡したパッチです。
`python`・`node`・`ruby`・`perl` にその場で渡したコードも、書き込みの API を呼んでいれば調べます。
リダイレクトは、手で文面を作るコマンド（`echo`・`printf`・`cat`・`sed`・`awk`・その場で渡したコード）の出力だけを調べます。コマンドの中の `cd` も辿ります。

生成ファイルを読むだけの操作と、生成コマンドやスクリプトファイルの実行は、出力をリダイレクトしていても止めません
（`make l10n`、`go generate`、`python3 tools/gen.py`、`mockgen ... > x_mock.go`）。

止めたときは、生成元を直して作り直すようエージェントに伝えます。マーカーから生成コマンドが読めれば（`'make l10n'` や mockgen の `Generated by this command:` など）、そのコマンドを示します。生成コマンドを実行できないときは、作業を続けて必要な変更を最終報告に書くよう伝えます。確認は求めません。

Go の慣習に沿わない生成ファイルのマーカーは、`~/.config/hhx/config.yaml` に足します。各項目は Go の正規表現で、ファイルの先頭に行単位で当てます。

```yaml
hooks:
  generated-edit-guard:
    markers:
      - "^// auto generate by 'make l10n'"
```

ユーザーが生成ファイルの編集を明示的に指示したときは、エージェントが次を 1 回実行します。

```sh
hhx allow-generated-edit --reason "<ユーザーの指示>" path/to/file.go
```

hook はこの宣言をエージェントのセッションに記録し、そのセッションの間は指定したパスの編集を通します。そのたびに、編集したファイル・理由・作り直しが必要なことを最終報告に書くようエージェントに伝えます。

静的な検査なので、変数で組み立てたパス、スクリプトファイルからの書き込み、`xargs` やファイルの削除などは検出しません。
